# Замер памяти: Binary Quantization

Дата: 2026-11-18. Машина: Windows, Docker Desktop, контейнер `qdrant/qdrant`.

## Методика

- Одинаковый набор: **37 000 точек**, размерность **384** (эмбеддинги `bge-small-en-v1.5`,
  чанки корпуса, повторённые 1000 раз — для замера памяти это корректно,
  для замера качества нет).
- Три конфигурации, каждая в отдельном прогоне:
  1. `float32`, векторы в RAM;
  2. Binary Quantization, `always_ram=True`, оригиналы в RAM;
  3. Binary Quantization, `always_ram=True`, оригиналы **на диске** (`on_disk=True`).
- Между прогонами: удаление коллекций и перезапуск контейнера, чтобы база была чистой.
- Память: `docker stats --no-stream`, колонка `MemUsage`, до и после индексации.
- Базовая линия (пустой Qdrant): **25.8–26.2 MiB**.

## Результаты

| Конфигурация | RSS до | RSS после | Прирост |
|---|---|---|---|
| float32, векторы в RAM | 25.96 MiB | **218.0 MiB** | **192.0 MiB** |
| BQ, оригиналы в RAM | 25.82 MiB | 157.7 MiB | 131.9 MiB |
| BQ, оригиналы на диске | 26.18 MiB | **96.4 MiB** | **70.2 MiB** |

**Вывод:** при хранении оригиналов на диске квантизация уменьшает прирост памяти
с 192 до 70 МиБ — примерно **в 2.7 раза** (≈63%), а не в 32 раза.

## Почему не 32×

32 — это отношение размера самих векторов: `37 000 × 384 × 4 байта = 54.2 МБ`
против `37 000 × 384 / 8 = 1.69 МБ`. Совпадает с документацией Qdrant.

Но в RSS попадает не только векторное хранилище: там же HNSW-индекс, payload,
структуры оптимизатора и служебные буферы. Они не сжимаются квантизацией,
поэтому по процессу в целом выигрыш скромнее.

## Важный побочный результат

Если оставить оригиналы в памяти (`always_ram=True` без `on_disk`), квантизация
**увеличивает** потребление: к обычным векторам добавляются квантованные.
Первый прогон, где обе коллекции жили одновременно, дал 149 МиБ прироста для BQ
против 114 МиБ для обычной — то есть «квантизация = экономия» верно только вместе
с вытеснением оригиналов на диск.

## Ограничения замера

- Одна машина, один прогон на конфигурацию; разброс RSS между перезапусками ~1 МиБ.
- Размерность 384 (для 1024 ожидается больший абсолютный выигрыш при том же отношении).
- Качество поиска при квантизации здесь не измерялось — для этого нужен прогон
  `eval_retrieval.py` на серверной коллекции с rescoring.
